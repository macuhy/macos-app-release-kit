# 06 · 本实例配置与踩坑记录（macuhy / Kown）

> 本文件记录本套件在 **macuhy 组织 + Kown App** 上的真实落地配置与调试中踩到的坑，供以后新增 App 或排障时直接参考。

## 1. 组织与仓库结构

全部在 GitHub 组织 **`macuhy`** 下（个人账号升级路线；个人账号无组织级 secret，故建组织）：

| 仓库 | 角色 | 可见性 |
|------|------|--------|
| `macuhy/macos-app-release-kit` | 工具库：reusable workflow + 脚本 + 模板 | 公开 |
| `macuhy/kown` | App 源码，`git tag vX.Y.Z` 在此触发发布 | 私有 |
| `macuhy/kown-mac` | 公共分发：Release 产物（`Kown.zip`）+ `appcast.xml` | 公开 |

## 2. 发布路线：CI（放弃本地脚本）

- **采用**：打 tag → GitHub Actions（调用 kit 的 reusable workflow）自动签名/公证/打包/发 appcast。
- **放弃**：`kown/scripts/release.sh` 本地发布脚本（它走 `swift build` + 本机钥匙串，与 CI 路线重复）。如需彻底清理可删除该脚本。

## 5. 踩坑记录（关键！新 App 接入照此避坑）

1. **`startup_failure`（1 秒失败，无 job）**
   根因：新建组织/仓库默认 `GITHUB_TOKEN` 权限是 **read-only**，而 reusable workflow 顶部声明 `permissions: contents: write`，被调用方权限不能超过调用方 → 启动即失败。
   **修复**：调用方 workflow 加顶层 `permissions: contents: write`（已写进 `templates/caller-workflow.yml`）。

2. **`Secret X is required, but not provided`（secrets: inherit 不生效）**
   根因：**跨仓库**调用 reusable workflow 时，`secrets: inherit` 不会转发组织级 secret。
   **修复**：调用方**显式逐个传** `secrets: { NAME: ${{ secrets.NAME }} }`（已写进 `templates/caller-workflow.yml`）。

3. **`SecKeychainItemImport: Unable to decode the provided data`（Install certificate）**
   根因：`DEVELOPER_ID_CERTIFICATE_P12` secret 的 base64 值损坏/不是有效 p12。
   **排查**：reusable workflow 的 Install certificate 步骤已加诊断——打印解码字节数、结尾 `security find-identity` 确认身份。设 secret 时务必 `base64 -i cert.p12 | tr -d '\n'` 单行、且源文件用 openssl 验证过含 Developer ID Application + 私钥。

4. **Archive 签名冲突 + iCloud 需要 provisioning profile**
   - 报错① `conflicting provisioning settings ... Developer ID Application has been manually specified`：project.yml 是 `CODE_SIGN_STYLE: Automatic`，archive 又手动指定 Developer ID → 冲突。
   - 报错② `"Kown" requires a provisioning profile with the iCloud feature`：带 iCloud entitlement 的 Developer ID 包必须有 provisioning profile。
   **修复**：archive 用 `CODE_SIGN_STYLE=Manual` + `PROVISIONING_PROFILE_SPECIFIER="Kown Developer ID"`；ExportOptions 用 `signingStyle=manual` + `provisioningProfiles` 映射 `com.xiaobo.kown → Kown Developer ID`；profile 存成 `PROVISIONING_PROFILE_BASE64` secret，CI 里安装到 `~/Library/MobileDevice/Provisioning Profiles/`。reusable workflow 已用 `provisioning_profile_specifier` 输入支持此流程（普通无受限 entitlement 的 App 留空即可）。

5. **XcodeGen spec 在子目录**
   `mac/project.yml` 不在仓库根，CI 里直接 `xcodegen generate` 找不到 spec。
   **本实例做法**：本地 `cd mac && xcodegen generate` 生成并**提交** `mac/Kown.xcodeproj`，调用方设 `use_xcodegen: false`，CI 直接构建已提交工程。改了 `project.yml` 后记得本地重生成再提交。

## 6. 触发发布

```bash
# 在 macuhy/kown 仓库
git tag v0.4.3 && git push origin v0.4.3      # 或 Actions 页 workflow_dispatch 填版本号
```
产物 `Kown.zip` 发到 `macuhy/kown-mac` 的 Release，`appcast.xml` 自动更新；App 内 Sparkle 据此检查更新。
