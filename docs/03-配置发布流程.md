# 03 · 配置并触发发布流程

## 工作流做了什么
`templates/release.yml`（放在私有仓库 `.github/workflows/release.yml`）在你推送 `v*` tag 时：

1. 导入签名证书到 CI 临时钥匙串
2. `xcodebuild` 编译（开启 Hardened Runtime）
3. 打包成 `.dmg`（`create-dmg`）
4. `notarytool` 公证 + `stapler` 装订票据
5. Sparkle `sign_update` 签名 + `generate_appcast` 生成 `appcast.xml`
6. 用 PAT 在**公共仓库**创建 Release 上传 DMG，并提交 `appcast.xml`

## 触发一次发布
```bash
cd <私有仓库>
# 版本号即 tag；建议遵循 vX.Y.Z
git tag v1.0.0
git push origin v1.0.0
```

在 `https://github.com/{{PRIVATE_REPO}}/actions` 观察运行。成功后：
- 公共仓库 Releases 出现 `v1.0.0` + `{{APP_NAME}}.dmg`
- 公共仓库根目录 `appcast.xml` 已更新

## 验证发布成功
```bash
# 1) DMG 已发布
gh release view v1.0.0 --repo {{PUBLIC_REPO}}

# 2) appcast 指向正确的下载地址且含签名
curl -s {{APPCAST_URL}} | grep -E "sparkle:edSignature|enclosure url"
```

## 常见失败排查
| 现象 | 原因 / 解决 |
|------|------------|
| 公证 `Invalid` | `xcrun notarytool log <id> --apple-id ...` 看详情；多半是没开 Hardened Runtime 或缺 entitlements |
| codesign 报无证书 | `BUILD_CERTIFICATE_BASE64` / `P12_PASSWORD` 不对，或证书不是 Developer ID Application |
| 发布到公共仓库 403 | `RELEASE_REPO_PAT` 权限不足，需 Contents: Read and write 且选中公共仓库 |
| App 检测不到更新 | build 号没递增（见下）/ `SUFeedURL` 写错 / appcast 的 enclosure URL 404 |

## build 号自动递增
workflow 已用 `git rev-list --count HEAD` 写入 `CFBundleVersion`，保证每次提交都递增。
若你手动管理版本，确保 `CFBundleVersion` 每次发布都比上次大。
