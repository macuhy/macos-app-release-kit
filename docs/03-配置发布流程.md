# 03 · 配置并触发发布流程

## 工作流做了什么
reusable workflow（公共 kit 仓库 `.github/workflows/release-reusable.yml`）在被调用时：

1. checkout 源码 + 拉取 kit 脚本
2.（可选）`xcodegen generate` 生成工程
3. 算版本：tag 或手动输入；build 号 = `git rev-list --count HEAD`
4. 用**随机密码**创建临时钥匙串并导入证书
5. `notarytool store-credentials` 存公证凭据
6. `xcodebuild archive` → `-exportArchive`（配 `ExportOptions.plist`，Developer ID 方式）
7. ZIP 公证 + `stapler staple` 装订票据
8. 打分发 ZIP
9. Sparkle `sign_update` 签名，解析 `edSignature` / `length`
10.（手动触发时）给私有源码仓库打 tag
11. **用 PAT** 在公共仓库建 Release 上传 ZIP；克隆公共仓库，用 `update_appcast.py` 增量写入 `appcast.xml` 并推回
12. `if: always()` 清理钥匙串

## 需要放进 App 私有仓库的文件
- `.github/workflows/release.yml` ← 复制 `templates/caller-workflow.yml`（替换占位符）
- `ExportOptions.plist` ← 复制 `templates/ExportOptions.plist`（填 `{{APPLE_TEAM_ID}}`）

## 触发一次发布（两种方式）
**方式一：打 tag**
```bash
cd <私有仓库>
git tag v1.0.0
git push origin v1.0.0
```
**方式二：手动**
Actions 页 → 选 Release → Run workflow → 填版本号（如 `1.0.0`）→ 会自动打 tag 并发布。

## 验证发布成功
```bash
gh release view v1.0.0 --repo {{PUBLIC_REPO}}                       # DMG/ZIP 已发布
curl -s {{APPCAST_URL}} | grep -E "sparkle:edSignature|enclosure url"  # appcast 含签名与下载地址
```

## 常见失败排查
| 现象 | 原因 / 解决 |
|------|------------|
| 公证 `Invalid` | `xcrun notarytool log <id> --keychain-profile notarytool` 看详情；多半缺 Hardened Runtime 或 entitlements |
| export 失败 | `ExportOptions.plist` 的 `teamID`/`method` 不对 |
| codesign 无证书 | `DEVELOPER_ID_CERTIFICATE_P12` / `..._PASSWORD` 不对，或证书非 Developer ID Application |
| 发布到公共仓库 403 | `RELEASE_REPO_PAT` 权限不足（需 Contents: RW 且选中公共仓库），或已过期 |
| 解析 Sparkle 签名失败 | `SPARKLE_PRIVATE_KEY` 内容不完整/换行被破坏 |
| App 检测不到更新 | build 号没递增 / `SUFeedURL` 写错 / enclosure URL 404 |

## build 号自动递增
workflow 用 `git rev-list --count HEAD` 写入 `CURRENT_PROJECT_VERSION`（即 CFBundleVersion），保证每次提交都递增——Sparkle 据此判断新旧。
